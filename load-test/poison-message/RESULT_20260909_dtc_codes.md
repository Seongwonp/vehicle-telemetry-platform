# `dtc_codes` 배열 경계 — 배열을 문자열로 접는 자리에서 둘이 샌다 (2026-09-09)

| 항목 | 값 |
| --- | --- |
| **검증 상태** | **부분 검증(각 조건 1회)** |
| 적용 범위 | dev(평문) 프로파일, 파티션 3, 유형당 대조군 100건 |
| 코드 상태 | 작업 트리(`inject_poison.py`에 세 유형 추가) |
| 실행 명령 | `TYPES="dtc_null dtc_comma dtc_scalar" bash load-test/poison-message/run_scenario.sh 100` |
| 원본 증거 | `evidence/20260909-002052` (COMPLETE) |

`toPoint()`는 `String.join(",", telemetry.getDtcCodes())`로 **배열을 문자열 하나로 접는다.**
접는 순간 두 가지가 가능해지는데 둘 다 확인한 적이 없었다.

## 결과

| 유형 | 대조군 | 독성의 종착지 | 저장된 값 |
| --- | ---: | --- | --- |
| `"dtc_codes": "P0301"` (배열 아님) | 100/100 | DLQ(`permanent`) | — |
| **`"dtc_codes": [null]`** | **101/100** | **저장됨** | **`null`** (네 글자 문자열) |
| **`"dtc_codes": ["P0301,P0420"]`** | **101/100** | **저장됨** | **`P0301,P0420`** |

토픽 303건, DLQ **1건**(`MismatchedInputException` / `permanent`, `unknown` 0).
대조군은 세 유형 모두 전량 저장 — **독성이 정상 레코드를 막지 않는다.**

### 1. 배열이 아니면 역직렬화에서 걸린다 (예상대로)

```
Cannot construct instance of `java.util.ArrayList` ... no String-argument constructor
```

Jackson의 `ACCEPT_SINGLE_VALUE_AS_ARRAY`가 기본 꺼져 있어서다. `NaN`이 걸린 것과 같은 문
(역직렬화)이다.

### 2. `[null]`은 `"null"`이라는 글자가 되어 저장된다

`String.join`은 null 원소를 **문자열 "null"로 바꾼다**(NPE가 아니다). 그래서
DTC 코드 이름이 `null`인 것처럼 저장된다. DLQ 0, 에러 0, 카운터 0.

실제 OBD-II 코드는 `[PBCU]\d{4}` 형식이라 `null`은 **눈으로는 명백히 이상해 보인다.**
하지만 그건 사람이 볼 때 얘기고, **기계에게는 그냥 코드 하나**다.

### 3. 코드에 쉼표가 들어가면 구분자와 충돌한다

`["P0301,P0420"]`(코드 **1개**)와 `["P0301", "P0420"]`(코드 **2개**)는 저장된 문자열이
`P0301,P0420`으로 **똑같다.** 저장 데이터만 보면 되돌릴 수 없다.

실제 DTC 코드에는 쉼표가 없으므로 **스펙을 지키는 입력에서는 일어나지 않는다.**

## 이상 감지에는 영향이 없다

룰은 `anomaly-detector/rules.py`가 **원본 JSON**에서 평가한다 — "배열이 비어있지 않으면
이상"이다. `[null]`도 `["P0301,P0420"]`도 비어있지 않으므로 정상적으로 걸린다.
**저장된 표현만 손실이 있다.** `rpm: 2000.7`과 같은 구조다.

## 고치지 않기로 한다

이 프로젝트에서 조용한 값 변형을 고친 전례는 `speed: 1e309`다. 그때는
**필드 하나가 통째로 사라져서** "값이 없다"와 "0이다"를 구분할 수 없었다. 여기는 다르다.

1. **값이 사라지지 않는다.** `null`은 남아 있고, DTC 형식(`[PBCU]\d{4}`)에 안 맞아
   **명백히 이상한 값으로 보인다.** 조용히 사라지는 것과 눈에 띄게 틀린 것은 다르다.
2. **쉼표 충돌은 스펙 위반 입력에서만 생긴다.** 실제 DTC에는 쉼표가 없다.
3. **이상 감지에 영향이 없다**(위).
4. 막으려면 `finite()`처럼 예외를 던지거나 구분자를 바꿔야 하는데,
   구분자 변경은 **저장 포맷 계약을 바꾸는 것**이라 기존 데이터와 읽는 쪽이 전부 영향받는다.
   지금 들어오지도 않는 입력을 막으려고 그럴 이유가 없다.

**대신 기록해둔다**: `dtc_codes`는 저장 시 손실이 있는 유일한 필드다.
저장 데이터에서 코드를 다시 쪼개 세는 코드를 쓴다면 이 두 경우를 알고 써야 한다.
`toPoint()`의 해당 줄에 주석으로 남겼다.

**다시 볼 조건**: 실제 장치에서 null 원소나 쉼표 포함 코드가 **한 번이라도 관찰되면**
이 결정을 뒤집는다. 그때는 `finite()`와 같은 방식(예외 → DLQ)이 맞다.

## 이 문서의 한계

- **각 조건 1회**다. 예외 클래스로 갈리는 결정적 동작이라 회차 변동 요소는 적다.
- 빈 문자열 원소(`[""]`), 아주 긴 코드, 중복 코드는 **안 봤다.**
- `dtc_codes`를 저장 데이터에서 다시 쪼개 쓰는 코드는 현재 **없다**(그래서 실피해가 없다).
  나중에 생기면 이 문서를 먼저 봐야 한다.
- MQTT 경로로는 주입하지 않았다. 같은 `ObjectMapper`를 쓴다는 코드 근거만 있다.
