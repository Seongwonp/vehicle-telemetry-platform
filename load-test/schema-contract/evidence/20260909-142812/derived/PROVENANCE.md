# 파생 증거 — 원본이 아니다 (그리고 이 실행은 대체됐다)

이 파일들은 실행이 끝난 뒤 손으로 DLQ 토픽을 다시 읽어 만든 것이다. 처음에 실행
디렉터리 **최상위**에 두었다가 여기로 옮겼다 — 원본과 섞이면 안 되기 때문이다.
당시에는 수집 스크립트가 없어 명령을 직접 쳤고, 그래서 아래 "생성 명령"이 스크립트가
아니라 파이프라인이다. **이후 실행은 `collect_dlq_attribution.sh`가 만든다.**

| | |
| --- | --- |
| 생성 방식 | 손으로 실행한 `kafka-console-consumer` 파이프라인 (스크립트 없음) |
| 입력 (원본) | Kafka 토픽 `vehicle-telemetry-dlq`, `vehicle-telemetry-mqtt-dlq` |
| 무결성 | 이 디렉터리의 `checksums.txt` — 상위 실행 매니페스트와 별개 |
| 재현 | **불가.** 다음 실행(`20260909-145736`)이 `down -v`로 토픽을 비웠다 |

## 이 실행(20260909-142812)의 위치 — 유효하지만 **대체됐다**

19/19 PASS는 그 시점 코드에 대해 유효하다. 다만 그 뒤에 `TelemetryDecoder`에
**JSON `null` 리터럴 가드**가 추가됐고, 이 실행의 이미지에는 그 수정이 없다
(이미지 빌드 14:21 / 가드 추가 14:39).

**그래서 최종 코드에 대한 E2E 근거는 이 실행이 아니라 `20260909-145736`(21/21)이다.**
시나리오도 `null_literal` 두 칸이 늘었다. 이 디렉터리는 지우지 않고 남긴다 —
"무엇이 언제 검증됐는지"의 기록이다.
