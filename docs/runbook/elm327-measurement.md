# ELM327 실측 절차

상태: **미실행**. 2026-10-01 Windows Win32_SerialPort 조회는 0건이었다. Bluetooth/Wi-Fi 장비 부재를 증명하는 결과는 아니며, 연결 방식·차량·브리지 실행 경로가 필요하다.

## 사전 조건

- 차량·동글 연결 방식과 포트를 확인한다. 운행 중 운전자가 장비를 조작하지 않는다.
- 읽기 전용 OBD 요청만 사용한다. DTC 삭제·ECU 쓰기·액추에이터 제어를 실행하지 않는다.
- 동글 모델·차량 정보는 공개 가능한 수준으로 기록하고 VIN·GPS 원문은 공개 증거에서 제외한다.
- 시뮬레이터 출력과 실차 출력을 구분한다. PID 미지원 값을 0으로 만들어 정상 관측처럼 전송하지 않는다.

## 정차 벤치

1. 지원 PID를 조회한 뒤 010D·010C·0105·0111·012F·0142의 지원 여부를 기록한다.
2. 요청·응답 시각, 실제 폴링 간격, timeout·NO DATA·파싱 실패를 기록한다. 단위 변환을 샘플 원문과 대조한다.
3. 5분 정상 대조군 후 동글 연결을 끊었다 복구한다. 연결 실패 중 마지막 값을 새 관측처럼 재발행하지 않는지 확인한다.
4. MQTT 단절 후 보관·재전송한다. 차량 측 PUBACK과 서버 Kafka 저장을 별도 열로 대조한다.

## 반복 주행

정차 벤치 성공 후 30분씩 3회. 성공 기준은 실행 전에 기록한다: 입력·발행·PUBACK·Kafka·최종 저장의 메시지별 차이 설명, 결측을 정상값으로 위장하지 않기, 재연결 결과 보존. 수집 주기는 장비 실측으로 정하며 처리량 상한의 증거로 쓰지 않는다.

기록 필드: 실행 ID, 소스 commit/dirty diff, 장비·연결 방식, PID, request/response 시각, 상태, 값·단위, 로컬 메시지 식별자, 발행·PUBACK·서버 확인 시각. 원본은 비공개 보관하고 공개 샘플은 식별정보 제거 후 checksum을 기록한다.
