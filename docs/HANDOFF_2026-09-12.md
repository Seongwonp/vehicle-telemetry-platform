## 2. 이번에 닫은 것 — roadmap 3번 Redis 장애 정책

### 2-1. 정책은 **한 방향으로 묶지 않았다**

| 경로 | 정책 | Redis 중지 중 (실측, 각 1회) |
| --- | --- | --- |
| 일반 조회 | **fail-open** | **200** (2.01s) — 제한만 못 걸고 데이터는 정확하다 |
| 진단 | **fail-closed** | 503 `REDIS_UNAVAILABLE` (4.02s) |
| 로그인 보호·refresh | **fail-closed** | 503 `REDIS_UNAVAILABLE` (2.01s) |
| `health/liveness` | 외부 의존 제외 | **200** (8ms) — 재시작 대상 아님 |
| `health/readiness` | Redis 포함 | 503 — 라우팅에서 제외 |

**조회 fail-open과 로그인 fail-closed가 반대 방향인 것이 핵심이다.** 하나로 묶으면
조회를 살리려다 **Redis를 죽이는 것이 곧 brute force 방어를 끄는 방법**이 된다.

### 2-3. **읽을 때 틀리기 쉬운 것 셋**

1. **`telemetry_ratelimit_failopen_total`은 "통과한 요청 수"가 아니다.**
   뜻은 "일반 rate limit이 적용되지 않은 요청 수"다. 진단 요청은 인터셉터를 둘 타서
   **`failopen`과 `redis_unavailable`에 동시에 오른다** — 버그가 아니다.
2. **fail-open은 "빠르다"를 사지 않았다.** 통과하되 Redis timeout까지 2초를 쓴다
   (진단은 인터셉터 둘이라 4초). 회로 차단기는 넣지 않았다.
3. **복구 시간이 관측마다 달랐다** — 8초(오전)와 30초(오후). **원인 미확인.**
   각 1회씩이라 "8~30초"라는 범위 주장도 못 한다.

## 5. 하면 안 되는 것

- **`docker compose down -v`** — 볼륨이 날아간다. 사용자 요청이 있을 때만.
- **다른 프로젝트 컨테이너를 건드리지 않는다**(예: `csat-forge-redis`).
- **`evidence/`를 지우지 않는다.** 무효한 실행도 사유를 적어 남긴다.
- **원격 히스토리를 다시 쓰지 않는다**(rebase/force-push 금지).
- **커밋에 AI 공동저자 트레일러를 넣지 않는다.** 세션 마지막 커밋만 `마지막커밋:` 접두사.
- **지표 라벨에 차량 ID·payload·예외 메시지·필드 경로를 넣지 않는다.**
- **비밀은 문서에 넣지 않는다** — 경로와 변수 이름까지만.
- **커밋·푸시는 사용자가 명시적으로 요청할 때만.**
- **fail-closed 경로(`DiagnosisRateLimitInterceptor`, `LoginRateLimiter`,
  `BruteForceDetector`)에 try/catch를 넣지 않는다** — 넣는 순간 조용히 fail-open이 된다.
  `FailClosedPathsTest`가 막지만, 테스트를 고쳐서 통과시키지 마라.

3. **코드 주석에만 숫자를 적고 증거를 안 남겼다**(`p50 0.175ms`). 다시 재서
