## 3. 다음에 할 일 — **사용자 결정이 먼저다**

`docs/redis-failure-policy.md` §3-2의 네 항목이 열려 있다. **결정 없이 구현하지 마라.**

| # | 질문 | 내가 기운 쪽(확정 아님) |
| ---: | --- | --- |
| ② | 일반 조회 rate limit을 **fail-open**으로 열까 | fail-open. 단, 지표·로그로 "지금 제한이 안 걸린다"가 보여야 함 |
| ③ | 진단 rate limit은 어느 쪽인가 | **모름** — 진단 호출의 비용 성격을 모른다 |
| ④ | 로그인 보호(brute force) | **fail-closed**. fail-open이면 Redis를 죽이는 것이 곧 방어를 끄는 방법이 된다 |
| ⑥ | health에서 Redis를 분리 표시할까 | 지금은 Redis 하나로 인스턴스가 교체 대상이 된다 |

**②와 ④가 반대 방향인 것이 요점이다.** "Redis 장애 시 fail-open" 하나로 묶으면
보안 통제를 끄게 되고, "fail-closed" 하나로 묶으면 조회까지 막힌다.

결정이 나면 할 일(§5): 그룹별 fail 정책 구현 + 그 상태를 나타내는 지표,
30/90초 지속 장애 실험, 스레드 고갈 임계 측정, Runbook에 fail-open 절차 추가.

**결정을 기다리는 동안 할 수 있는 것**: roadmap 4번(이벤트 상관관계 `event_id`) —
Redis와 독립적이다.

## 5. 하면 안 되는 것

- **`docker compose down -v`** — 볼륨이 날아간다. 사용자 요청이 있을 때만.
- **다른 프로젝트 컨테이너를 건드리지 않는다**(예: `csat-forge-redis`).
- **`evidence/`를 지우지 않는다.** 무효한 실행도 사유를 적어 남긴다.
- **원격 히스토리를 다시 쓰지 않는다**(rebase/force-push 금지).
- **커밋에 AI 공동저자 트레일러를 넣지 않는다.**
- **지표 라벨에 차량 ID·payload·예외 메시지·필드 경로를 넣지 않는다.**
- **비밀은 문서에 넣지 않는다** — 경로와 변수 이름까지만.
- **커밋·푸시는 사용자가 명시적으로 요청할 때만.**

## 6. 이번 세션에서 틀렸던 것 (반복 방지)

1. **빌드 실패를 가린 채 측정했다.** `build backend >/dev/null 2>&1 && echo "빌드 완료"` —
   실패했는데 "완료"가 찍혔고 낡은 이미지를 쟀다. **빌드 출력을 가리지 마라.**
   증거에 이미지 ID와 컨테이너의 이미지 ID를 나란히 적는 습관을 넣었다.
2. **`MeterRegistry`를 생성자 필수 의존으로 걸어 `@WebMvcTest`를 다 깨뜨렸다.**
   `ObjectProvider`로 바꿨다. **계측이 본체의 생존 조건이 되면 안 된다.**
3. **코드 주석에만 숫자를 적고 증거를 안 남겼다**(`p50 0.175ms`). 다시 재서
   `redis-normal-latency.csv`로 남겼다.
